Scope and interpretation

This sample depicts a hypothetical application containing a chat interface, retrieval component, text-processing service and monitoring pipeline. It does not establish that the application exists, that any tool was run, or that any security issue is present.

Execution status describes whether a test ran. Finding status describes the assessor's conclusion. These are independent. A tool alert, score, drift signal or generated response is not automatically a vulnerability.

Validation required before confirmation

  • Run the selected test against an authorised target with recorded tool version and configuration.
  • Retain sanitized primary evidence, timestamps and correlation identifiers.
  • Reproduce behaviour and rule out harness, parser, detector or configuration artefacts.
  • Establish affected security boundary, attacker preconditions and impact.
  • Map to taxonomy/OWASP only where evidence supports it; document rationale.
  • Assign severity using the main framework's risk methodology and record reviewer disposition.
